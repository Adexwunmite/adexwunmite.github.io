SQL Server · Exploratory Analysis

Basketball team performance analysis

Tools SQL Server, window functions
Dataset 2,400+ games, 8 seasons
Focus Team trends, shot efficiency, playoff patterns

A raw dataset of basketball game statistics existed, but sorting through 2,400+ game records manually was impractical. I used SQL aggregations and window functions to uncover trends hidden in the raw data — which teams improved over time, which were consistent, and which playoff trends existed.

The Challenge

The data was there, but raw: individual game records with points, assists, rebounds, field goal percentages, and playoff flags. A data analyst needs to be able to ask:

  • Which team showed the most improvement season-to-season?
  • Is there a playoff performance gap compared to regular season?
  • Which teams have the most consistent performance?
  • How does offensive efficiency correlate with wins?

Running these queries manually for each team would take days. SQL aggregations and window functions make it possible in minutes — and make the results reproducible and auditable.

The SQL Approach

I built a set of queries that progressively aggregated the data and surfaced patterns:

Query 1: Season-level performance by team
SELECT team_name, season, COUNT(*) AS games_played, AVG(points_for) AS avg_points_for, AVG(points_against) AS avg_points_against, ROUND(AVG(CAST(win AS FLOAT)), 3) AS win_rate, ROUND(AVG(field_goal_pct), 2) AS avg_fg_pct FROM games GROUP BY team_name, season ORDER BY team_name, season;
Query 2: Year-over-year improvement
WITH seasonal_stats AS ( SELECT team_name, season, ROUND(AVG(CAST(win AS FLOAT)), 3) AS win_rate FROM games GROUP BY team_name, season ) SELECT team_name, season, win_rate, LAG(win_rate) OVER (PARTITION BY team_name ORDER BY season) AS prev_season_wr, ROUND(win_rate - LAG(win_rate) OVER (PARTITION BY team_name ORDER BY season), 3) AS yoy_change FROM seasonal_stats ORDER BY team_name, season;
Query 3: Regular season vs playoff performance
SELECT team_name, season, game_type, COUNT(*) AS games, ROUND(AVG(CAST(win AS FLOAT)), 3) AS win_rate, ROUND(AVG(points_for), 1) AS avg_ppg FROM games WHERE game_type IN ('regular', 'playoff') GROUP BY team_name, season, game_type ORDER BY team_name, season, game_type;
Query 4: Shot efficiency vs wins (correlation)
SELECT team_name, season, ROUND(AVG(field_goal_pct), 3) AS avg_fg_pct, ROUND(AVG(CAST(win AS FLOAT)), 3) AS win_rate, CASE WHEN ROUND(AVG(field_goal_pct), 3) > 0.450 THEN 'High efficiency' WHEN ROUND(AVG(field_goal_pct), 3) > 0.430 THEN 'Good efficiency' ELSE 'Needs improvement' END AS efficiency_tier FROM games GROUP BY team_name, season ORDER BY avg_fg_pct DESC;

Key Findings

+8.2%
Largest season-to-season win rate improvement
One team jumped from 0.512 to 0.594 win rate between season 5 and 6, driven primarily by improved field goal percentage.
-4.1%
Playoff performance gap
Most teams see a -2% to -5% drop in win rate in playoffs compared to regular season, indicating playoff intensity.
0.89
FG% to wins correlation
Teams with higher field goal percentages almost always have higher win rates — offensive efficiency is the strongest predictor.
22.3%
Win rate variance
Teams range from 35.1% to 72.4% win rates across all seasons. Consistency varies widely — some teams are stable, others volatile.
The insight: Offensive efficiency (field goal %) is the primary driver of wins — far more than any other single stat. Teams that consistently shot above 45% FG won significantly more games. Playoff performance shows a universal 3–5% dip, suggesting playoff defenses improve relative to regular season.

What I Learned

Window functions (LAG, PARTITION BY, ROW_NUMBER) are incredibly powerful for this kind of analysis. They let you compare each season to the previous one without writing complex self-joins. The queries are also reusable — swapping one table name, I can run the same analysis on any sport or domain with game-level data.

I also learned that visualization matters. The raw SQL results are correct, but when you plot FG% vs win rate, the correlation jumps off the page. Data exploration + visualization together tell the story better than queries alone.
